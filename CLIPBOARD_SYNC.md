# Общий буфер VibeDictate между Mac

Синхронизация передаёт новые копирования между работающими экземплярами VibeDictate
в одной локальной сети. Текст, изображения и обычные файлы появляются в буфере
другого Mac; вставка выполняется привычным ⌘V. Интернет, облачный сервер и Apple ID
для этой функции не нужны. Диктовка продолжает работать своим прежним путём.

## Подключить два или несколько Mac

1. Установите сборку VibeDictate с этой функцией на каждый Mac. Подключите
   компьютеры к одной локальной сети и запустите приложение на всех компьютерах.
2. На первом Mac откройте настройки приложения → **Буфер** → **Создать группу**.
   Сохраните появившийся код в надёжном месте. Это секрет доступа ко всему буферу
   группы, а не короткий одноразовый PIN.
3. На каждом следующем Mac откройте ту же вкладку, введите код первого Mac в
   **Код группы** и нажмите **Подключиться**. Не создавайте отдельную группу на
   каждом компьютере: разные коды означают разные группы.
4. Включите **Синхронизировать буфер между Mac** на каждом компьютере. Если macOS
   попросит доступ к локальной сети, разрешите его VibeDictate.
5. Дождитесь сообщения о найденных Mac. Скопируйте новый текст на первом Mac,
   дождитесь сообщения об отправке/получении и нажмите ⌘V на втором.

Третий и последующие Mac подключаются тем же кодом. Приложение ищет соседей через
Bonjour; маршрутизация между разными сетями и облачная доставка не предусмотрены.
Одновременно обнаруживается до 8 других Mac. Спящие и выключенные компьютеры
пропускают передачу: очереди для последующей доставки нет.

**Пауза** временно останавливает отправку и получение на данном Mac; **Продолжить**
возобновляет их. Выключение переключателя сохраняет код группы. После включения
старое содержимое буфера само не отправляется: скопируйте его заново или нажмите
**Отправить текущий буфер**. Временные и секретные данные не отправляются даже этой
кнопкой. Получение меняет только буфер и не нажимает ⌘V за пользователя.

Если код уже сохранён, его можно открыть кнопкой **Показать сохранённый код**
и подключить ещё один Mac. Кнопка **Скопировать код** помечает такое копирование
как секретное и исключает его из сетевой передачи.

## Что передаётся

| Содержимое                                                  | Поведение                                                                         |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Обычный текст                                               | Самостоятельные представления текста в Unicode                                    |
| Форматированный текст                                       | HTML и RTF, если приложение-источник положило их в буфер                          |
| Изображения                                                 | PNG, TIFF, JPEG; PDF-представление также поддерживается                           |
| Файлы из Finder                                             | Передаются сами байты обычных файлов, затем создаются локальные копии для вставки |
| Папки, символьные ссылки, специальные файлы                 | Не передаются                                                                     |
| Объекты с собственным форматом приложения и обещанные файлы | Полная совместимость не гарантируется; частные форматы не передаются              |

Лимит одной передачи в приложении — **20 МиБ** суммарно по всем представлениям
содержимого, до **16 файлов**, до **32 элементов** буфера. Для изображения выбирается
одно читаемое представление: сначала PNG, затем JPEG, затем TIFF. Остальные
изображения того же элемента не загружаются. Протокольный предел зашифрованного
сообщения — 64 МиБ, он не
увеличивает пользовательский предел. Слишком большой буфер остаётся локальным.

Файлы передаются как отдельные обычные файлы: права доступа, дата изменения,
расширенные атрибуты, resource fork и исходное расположение не переносятся.
Скрытые имена, небезопасные имена и повторяющиеся имена в одной передаче
отклоняются. Для передачи папки сначала создайте ZIP-архив в Finder.
Полученные файлы не открываются автоматически. Для постоянного хранения
вставьте их в выбранную папку Finder; временные локальные копии не являются
резервной копией.

Кэш полученных файлов ограничен **200 МиБ**. Файлы старше семи дней удаляются
при следующем получении файлов; фоновая очистка по часам не выполняется.
При заполнении кэша новая передача файлов отклоняется, поэтому нужные файлы
следует заранее сохранить в постоянную папку. Каталоги кэша имеют права 0700,
сами файлы — 0600; разрешение на запуск от источника не переносится.
Кнопка **Удалить полученные файлы** очищает этот кэш с подтверждением и оставляет
код группы. После очистки прежние ссылки на эти файлы в буфере перестанут
вставляться; сначала сохраните нужные файлы в Finder.

## Приватность и безопасность

Содержимое защищено AES-GCM с общим случайным ключом группы размером 256 бит.
Код хранится в Связке ключей этого Mac; у отладочной и обычной сборок отдельные
хранилища. По локальной сети видны факт работы сервиса и идентификаторы группы и
устройства. Имя компьютера и сам код в объявления Bonjour не включаются.
Перед передачей содержимого обе стороны подтверждают владение ключом группы
через новый случайный запрос; записанное ранее сетевое сообщение не заменяет
это подтверждение. Отправитель получает зашифрованное подтверждение приёма
сообщения. Оно подтверждает передачу, а результат обновления буфера следует
проверять по статусу на принимающем Mac.

Любой, кто получил код группы, может получать и менять буфер её компьютеров.
Для отключения потерянного компьютера создайте новую группу на оставшемся Mac
и введите новый код на всех доверенных компьютерах. Создание группы меняет код
на текущем Mac; остальные сохраняют прежний код до ручной замены.

Приложение пропускает данные с системными метками секретного, временного и
автоматически созданного буфера, собственные служебные копирования диктовки и
уже полученные сетевые данные. Это предотвращает обычные петли синхронизации
и передачу временного текста при вставке диктовки. Однако метки секретности
выставляет приложение-источник: пароль, скопированный как обычный текст без
метки, неотличим от любого другого текста и будет передан. Перед таким
копированием используйте **Паузу**.

Функция не передаёт буфер в AssemblyAI или OpenRouter и не добавляет его в журналы
диктовок. Это отдельный сетевой сервис; функции записи, распознавания и вставки
диктовки остаются отдельными. Обычная работа приложения с контекстом диктовки
имеет собственные правила, описанные в [AGENTS.md](AGENTS.md).

## Если связь не работает

- Проверьте одинаковый код и включённый переключатель на всех Mac, отсутствие
  паузы, запущенное приложение и бодрствующие компьютеры.
- Проверьте разрешение VibeDictate в настройках macOS → **Конфиденциальность и
  безопасность** → **Локальная сеть**, если такой раздел доступен в вашей версии
  системы. Bonjour и локальные соединения подчиняются разрешению macOS;
  технические требования описаны в
  [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy).
- Гостевая Wi-Fi-сеть с изоляцией клиентов, VPN или правила сетевого экрана могут
  мешать обнаружению. Используйте обычную домашнюю локальную сеть с разрешённой
  связью устройств между собой. IP-адрес вручную вводить нельзя.
- Проверьте размер и формат буфера. Если файл ещё не загружен из iCloud или другой
  облачной папки, сначала дождитесь его локального скачивания.
- Включите автоматическую установку времени на Mac: сообщения имеют срок жизни
  120 секунд, а часы допускают только небольшое расхождение. При одновременных
  копированиях сервис старается сохранить более свежий локальный буфер; это не
  журнал всех копирований и не гарантия единого порядка при сетевых задержках.

## Приёмка на реальных компьютерах

Следующие сценарии — инструкция для ручной проверки. Их наличие в документе
не означает, что они уже выполнены на двух физических Mac.

| Сценарий                                            | Ожидаемый результат                                                                                |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| A → B и B → A: русский текст, emoji, переносы строк | Вставляется исходное содержимое без автоматической вставки и повторной сетевой отправки            |
| Изображение из Preview и скриншот                   | Вставляется изображение в поддерживающем его редакторе                                             |
| Форматированный текст из браузера                   | В редакторе сохраняется поддерживаемое HTML/RTF; обычное поле получает текст                       |
| Один файл и несколько файлов из Finder              | Создаются пригодные для вставки локальные копии, совпадают байты и имена                           |
| Три Mac с одним кодом                               | Новое копирование на A получают B и C; петли передачи не возникают                                 |
| Другой код на B                                     | B не получает содержимое A                                                                         |
| Пауза, выключение и перезапуск                      | На паузе/при выключении передачи отсутствуют; старый буфер при запуске не рассылается              |
| Менеджер паролей с секретной меткой                 | Копирование не отправляется даже кнопкой ручной отправки                                           |
| Диктовка с заранее скопированным текстом/картинкой  | Вставка и восстановление исходного буфера работают; временная диктовка на соседний Mac не приходит |
| Локальное копирование во время получения            | Более свежая локальная копия не заменяется устаревшей сетевой                                      |
| Папка, ссылка, >20 МиБ, >16 файлов                  | Передача отклоняется с понятным статусом; исходный буфер остаётся пригодным для локальной вставки  |
| Сон, выход из сети и повторное подключение          | Нет зависания; новое копирование после восстановления связи передаётся                             |
| Отказ в доступе к локальной сети                    | Статус сообщает проблему; диктовка продолжает работать                                             |

Автоматические тесты протокола и полный проектный gate запускаются через
`scripts/check.sh`. Их итог и фактические ограничения ручной проверки сохраняются
в передаче этапа, а не заменяются предположением о работе на разных компьютерах.
